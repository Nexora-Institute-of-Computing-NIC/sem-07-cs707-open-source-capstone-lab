# CS707 — Open Source Capstone Lab — PLAN

**Semester:** 7 · **Credits:** 2 · **Level:** Advanced-Professional
**Theory:** 0 hrs · **Lab:** 45 hrs · **Tools:** Git, GitHub, a real open-source project of your choice

## Course Format
The final open-source contribution course. By the end of the semester, the student has **at least three merged pull requests** in real open-source projects, one of which is non-trivial (a bug fix or a feature, not just documentation).

## Objectives

1. Operate confidently inside an unfamiliar open-source codebase.
2. Contribute meaningfully — not just documentation fixes.
3. Handle the social side of open source — reviews, criticism, iteration.
4. Build a public track record of contributions.

## Lab Modules

### Module 1 — Choosing and Understanding (3 labs)
1. Pick three candidate projects — evaluate on activity, maintainers, friendliness
2. Deep-read the chosen project — architecture, conventions, test setup
3. Find and classify 5 issues — good-first, medium, hard

### Module 2 — Small Contributions (3 labs)
4. First PR — documentation, typo fix, or comment improvement
5. Handle the first review — reply, revise, merge
6. Second PR — small bug fix with a test

### Module 3 — Substantial Contribution (4 labs)
7. Choose a non-trivial issue — a real bug or small feature
8. Write a design/approach comment on the issue before coding
9. Implement the fix with tests and documentation
10. Iterate through review until merge (or an honest write-up if rejected)

### Module 4 — Community Participation (3 labs)
11. Triage — comment helpfully on three issues you are not fixing
12. Review someone else's PR — respectful, specific feedback
13. Participate in a discussion — a design thread, mailing list, or Discord

### Module 5 — Portfolio and Reflection (2 labs)
14. Build the contribution portfolio — a single page linking to everything
15. Final reflection — what you contributed, what you learned, what you would do next

## Weekly Structure
Each lab = a `weekly/week-NN.md` covering:
- What I attempted
- What I actually shipped (link to PR/issue)
- What blocked me and how I escalated
- What I will do next week

## Deliverables

- `PORTFOLIO.md` — links to every merged PR, closed issue, and review comment
- `weekly/` — 15 weekly logs
- `reflection.md` — a 1,500-word final reflection
- At least 3 merged PRs (1 non-trivial)
- At least 3 helpful triage comments on issues

## Assessment

| Component | Weight |
| :--- | :---: |
| Merged PRs (quality, not just count) | 40% |
| Non-trivial contribution (bug fix or feature) | 25% |
| Community participation (triage, reviews) | 15% |
| Weekly logs and final reflection | 20% |

## Rules

- No drive-by contributions — each PR must reflect real engagement with the project.
- Rejected PRs count if the write-up honestly explains what happened.
- AI-generated PRs without understanding are an integrity violation — you must be able to defend every line in review.

## If a Contribution Is Rejected

A rejected PR is **not** a failure if:
- The approach was sound and well-argued
- The reviewer's concerns were engaged with seriously
- The student documents the disagreement honestly in the reflection

The write-up of a rejected PR is worth up to 60% of what a merged PR is worth, provided the reasoning is rigorous.
